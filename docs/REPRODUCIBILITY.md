# Reproducibility and release scope

The offline example and tests reproduce the behavior of selected public utilities on invented data. They do **not** regenerate the 0.88304 submission, train the historical ensemble, or evaluate CUHK-X accuracy.

## What runs here

From the repository root with Python 3.10 or later:

```bash
python examples/offline_demo.py
PYTHONPATH=src python -m unittest discover -s tests -v
```

These commands need no dataset, checkpoint, API credential or accelerator. They exercise constrained action decoding, group separation, response remapping and fixed agreement/fallback behavior. See the [code map](CODE_MAP.md) for the relationship between these utilities and the historical implementation.

The optional [frame-encoding example](../research/README.md) requires its separate dependencies, a local compatible OpenCLIP checkpoint and correctly formatted contact sheets obtained with appropriate permission. It preserves the four-tile preprocessing and normalized image embedding operation. Its manifest and cache format are new, so it is not a replacement for the original experiment's cache files. Pretrained inference was not rerun during portfolio packaging.

## What full reproduction would require

| Level | What would be required | Status of this release |
| --- | --- | --- |
| Utility behavior | Source plus generated test fixtures | Included |
| Frozen frame encoding | Local checkpoint, compatible dependency versions and permitted input sheets | Optional adapted code included; assets excluded |
| Historical training experiments | Complete source/configuration, authorized raw inputs, preprocessing inventories, model initialization and saved split definitions | Methodology and aggregate results described; complete pipelines and assets not bundled |
| Regeneration of the selected submission | Every routed component, exact option mappings, inherited baseline generator, trained models and hosted inference access | Not established by this repository |
| New-subject performance | The same deployable procedure run on organizer-held data | Not established by a public leaderboard score |

The inherited public baseline provided predictions without the complete specialist training/inference machinery needed to regenerate them. In particular, the submitted manner answers are not generated by the local manner experiments described here. [Baseline attribution](ATTRIBUTION.md).

Reconstructing a saved CSV from saved component outputs is an assembly replay. Reloading a trained checkpoint and reproducing held-out predictions is a model replay. Re-extracting features from raw video is an input replay. These are different claims; one does not establish the others. Hosted model responses can also change across service versions or calls, even with identical prompts.

## Contracts needed to rerun the research

The useful reproduction unit is a declared experiment with its own input and model identities. At minimum, retain:

1. **Inputs:** authorized source files, content hashes, modality presence, native frame counts, geometry and presentation timestamps. Keep TRAIN answers separate from inference inputs.
2. **Preprocessing:** selected native indices or FPS-resampling rule, crop coordinates, interpolation, channel conversion, normalization, padding and short-video behavior. Matching a tensor shape alone is insufficient.
3. **Model identity:** upstream checkpoint and revision, weight hash, exact implementation and processor configuration, evaluation/training mode, precision and device.
4. **Training:** person-group membership, inner/outer exclusions, FIT-only normalization and targets, complete hyperparameters and random seeds. Never silently substitute a new feature map into an old fitted head.
5. **Inference and evaluation:** a complete prediction commit, schema checks, fixed fallback policy, all physical attempts and their usage, fresh replay, then the declared paired comparison. A timeout or missing answer must not create a selectively graded denominator.

For the historical V-JEPA2 native64 extraction, recorded versions were PyTorch 2.14.0, torchvision 0.29.0, Transformers 5.16.1, NumPy 2.5.3 and safetensors 0.8.0. It used Apple MPS, float16 encoder inference, two PyTorch threads, batch size one view, and source snapshots of relevant library code. These are historical provenance facts, not the public package's dependency requirements or a tested portable lockfile.

The feature-extraction audit reproduced cached pooling exactly. Its separate encoder replay criterion allowed relative L2 error at most 0.02 and cosine similarity at least 0.999; that criterion was not a guarantee of bitwise equality on other hardware. The source and readout details are in [methodology](METHODOLOGY.md).

## Interpreting the reported results

Use [RESULTS.md](RESULTS.md) for dated aggregate results and [METHODOLOGY.md](METHODOLOGY.md) for experimental context. Different local studies used different references and denominators. The same development people were reused repeatedly; a second partition is a robustness check on reused data. Public score differences do not identify which individual changed answers were correct, and neither local development gains nor a component replay establish performance on the organizer's unseen private cohort.
